## Course description

Computer Science 1 is an introductory programming course using Python. The
course emphasizes algorithm design, problem-solving strategies, and program
design. Topics include variables, types, expressions, standard input/output,
control structures, functions, strings, collections, classes, objects, modules,
file input/output, searching, sorting, and the relationship between recursion
and iteration as time permits.

Students also practice explaining programs, testing and revising their work,
working with peers, using source control, connecting course work to career
goals, and using AI tools responsibly while remaining accountable for the
submitted work.

## Course purpose and learning promise

This class is intended to help students build a durable programming foundation
and prepare for a career that brings them joy. Students are not expected to
arrive already knowing how to program. The course is built around practice,
visible progress, explanation, revision, and asking for help.

By the end of the course, students should be able to:

1. Implement a Python program to solve a problem.
2. Evaluate a program designed to solve a problem.
3. Modify a program to solve a similar or extended problem.
4. Explain the problem, approach, code, output, and evidence that a solution
   works.
5. Use feedback, testing, peer discussion, and revision to improve a program.
6. Use AI and other resources as learning tools, verify their suggestions, and
   disclose meaningful assistance.

## General education connections

The course develops communication, computer literacy, critical thinking, and
creativity.

- **Written communication:** programming reports, project descriptions,
  reflections, and explanations of code and output.
- **Oral communication:** paired-programming explanations, show-and-tell,
  demonstrations, and optional recorded walkthroughs.
- **Computer literacy and problem solving:** producing, testing, debugging,
  and revising working programs.
- **Critical thinking:** defining a problem, identifying assumptions, checking
  evidence, comparing approaches, and evaluating AI output.
- **Creativity:** designing and building a Coding Odyssey / Choose Your Own
  Adventure project.
- **Professional development:** degree planning, career research, resume and
  GitHub/LinkedIn artifacts, and reflection on next steps.

## Weekly course rhythm

The default face-to-face rhythm is:

- **Monday:** introduce the technical concept, work through examples, and set
  the week's practice target. A short AI-as-tutor lesson may be included.
- **Wednesday:** paired programming, guided practice, debugging, and explaining
  an approach to another person.
- **Friday:** show-and-tell, demonstration, reflection, peer feedback, or
  project progress.

Students should expect to submit or demonstrate evidence of work, not merely
claim that a program was completed.

## Course activities and assignments

### Weekly coding practice

Complete three problems from the current chapter or propose comparable
problems. A submission normally includes:

1. A sentence describing what each problem asks.
2. An outline, flowchart, or pseudocode plan.
3. The code.
4. Representative output or test results.
5. A short explanation of why the solution works and what was learned.

Students may use the suggested Canvas/ZyBooks problems or an instructor-
approved substitution that practices the same concept.

### Paired programming

Work with a partner on current problems. Take turns driving and explaining.
Record the problem, approach, code changes, tests, each person's contribution,
and any outside or AI assistance. When both partners have completed the basic
work, use the time to extend, test, refactor, or explain the solution more
clearly.

### Show-and-tell and demonstrations

Demonstrate a working program or a meaningful attempt. Explain what happened,
what was difficult, what changed, and what you learned. If you cannot present
in class, submit a written or recorded demonstration with code, output, and
explanation.

### Coding Odyssey / Choose Your Own Adventure

Build a small creative program or game through staged checkpoints:

1. Idea and design.
2. Design plus initial code.
3. A partially working version with explanation and revision.
4. A working final version and reflection.

The final project should be understandable enough for another person to try,
show meaningful use of course concepts, and include evidence of testing and
revision. Creativity, clarity, playability/usefulness, explanation, and clean
code may earn bonus recognition.

## AI and outside-resource policy

AI tools may be used as learning and brainstorming tools when the assignment
allows them. Appropriate uses may include asking for an explanation of an
error, comparing two approaches, generating practice questions, revising a
draft, or getting feedback on code that the student can explain.

Students remain responsible for submitted work. AI-generated code or writing
must not be presented as wholly original without acknowledgment. Students must
be able to explain, test, verify, and, when necessary, correct the submitted
work. AI tools can be inaccurate, overcomplicated, or confidently wrong.

When AI materially contributes to an assignment, include a short disclosure,
for example:

> In completing this assignment, I used [tool] for [brainstorming,
> explanation, debugging, editing, or another role]. I verified the submitted
> work by [tests, comparison, documentation, or explanation].

Using another person's work, an AI system, or an outside resource without the
required disclosure or attribution may violate academic-integrity rules.

## Academic integrity and plagiarism

Academic integrity is expected and required. Work presented as a student's own
must be the student's own or properly documented. Sharing, copying, or doing
work together is permitted only when the assignment explicitly allows it and
each student's contribution is clear.

Students should consult the current SWOSU academic-integrity policy in the
Student Handbook and the university's current [Academic Integrity
Guidelines](https://www.swosu.edu/document/953/Academic-Integrity-Guidelines/).
