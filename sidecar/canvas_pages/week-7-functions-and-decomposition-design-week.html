Reasoning Odyssey Gate — Week 7 — Someone Else Must Be Able to Run This

What are we learning? Functions and decomposition — pulling a piece of behavior your world already has into its own named, reusable unit with a parameter and a return value, instead of copy-pasting the same logic wherever you need it.

What am I building/changing? Take one distinct action your world already does (the founding print, the decision, the loop) and pull it into its own function with at least one parameter and a return value. Call it from somewhere else. This is your world's first refactor: same behavior as before, now named and reusable.

How does my world connect? This is literally a refactor of work from Weeks 2–6 — you're not adding a new capability, you're giving an existing one a name and making it reusable.

What evidence do I keep? One World Bible line: what gate you passed, what broke — this is the first week where "what broke" is likely to mean something real, since refactors reveal bugs that were hiding in copy-pasted code.

Quick Check (pass/fail — all three required, no partial credit)

A function is defined with at least one parameter — not a zero-argument function that just reads globals.
The function returns a value — not just prints and returns None.
The function is called at least once from outside its own definition, and the world's behavior is unchanged from before the refactor.

Graded on two separate tracks, not averaged: this Quick Check (pass/fail) plus a holistic Light Build pass — Strong/Solid/Minimal bands, not a point-per-criterion rubric. A parameter that's present but ignored (dead parameter) does not pass in spirit — it must actually be used in the function body.

What exactly do I turn in? Your refactored world code with the new function defined and called, plus your World Bible entry. The suggested practice problem (turn an existing branching check into a function that returns a status label instead of printing it) can directly be your gate submission.

What carries forward? Week 8 applies this same functions habit to string processing — pulling text-parsing logic into functions as you build it, not bolting it on after.
