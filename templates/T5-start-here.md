# Start Here

Welcome to COMSC 1033 — Computer Science 1. This page only needs reading
once; after this week, each module's own **Overview** page (the first item
inside it) tells you what's happening that week and what's due.

## What this class is

A supportive class structure where you learn to program through lecture,
paired programming, and show-and-tell — with an AI-fluency strand and a
professional-development strand woven through every week. You are not
expected to arrive already knowing how to program. Practice, visible
progress, explanation, revision, and asking for help are the core of the
course.

## The weekly rhythm

Every class period (50 minutes) is 10–15 minutes presented, then 35–40
minutes of active work:

| Day | 10–15 min strand | 35–40 min active work |
|---|---|---|
| **Monday** | **Monday Moment** — AI fluency | Main topic of the week — lecture with live worked examples |
| **Wednesday** | **Wacky Wednesday** — professional minds | Paired programming |
| **Friday** | **Fun Friday** — professional minds | Show-and-tell |

Week 1 is the same across every one of Jeremy's courses: Monday is getting
the most out of this class and this semester; Wednesday is getting the
most out of your degree; Friday is getting the most out of your career.

## What you're asked to do every week

Six recurring artifacts, each with its own reusable template:

1. **Monday Moment practice assignment** — best practices for whatever the
   week's Monday Moment teaches.
2. **Wacky Wednesday reflection** — how the Wednesday professional-minds
   lesson ties into the week.
3. **Weekly topic reinforcement** — practice reinforcing the week's
   technical topic, done inside your Coding Odyssey project
   (`assignments/A2-coding-odyssey-project.md`) rather than a separate
   problem set — that week's Coding Odyssey gate or checkpoint *is* this
   artifact (see `assignments/A1-weekly-coding-practice.md`).
4. **Fun Friday reflection** — how the Friday professional-minds lesson
   ties into the week.
5. **Paired-programming report** — how you contributed to Wednesday's
   paired programming.
6. **Friday feedback report** — the feedback you gave in Friday's
   show-and-tell discussion.

## The standing assignments (A1–A6)

These aren't one-time hand-ins — they're policy documents and ongoing
project templates that apply across many weeks. Each one's first
appearance in the course is:

| Assignment | First appears |
|---|---|
| A1 — Weekly coding practice | Week 2 |
| A2 — Coding Odyssey project | Week 6 |
| A3 — Pair programming | Week 10 |
| A4 — Show-and-tell reflection | Week 14 |
| A5 — Final reflection | Week 16 |
| A6 — Professional pathway artifacts | Week 14 |

## What the course gives you

- Slide presentations in class, plus transcriptions of the class
  recordings.
- A written technical text covering the material being taught.
- A chat bot for discussing your ideas — a thinking partner, not something
  that writes your fixes or your solution code for you.
- Worked solution examples — nothing hidden.
- An automated feedback reply on every submission, so you're never waiting
  in silence.
- A shared class repository for code, ideas, and helping each other grow.
- A supportive class structure — the umbrella promise everything above
  serves.
